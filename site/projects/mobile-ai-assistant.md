# 魔介 AI 智能助手 H5

> 项目周期：2025.03 — 2025.04。本页日期为案例整理日期，不是项目开始时间。

## 业务背景

这是一个面向美妆领域的 AI 智能助手，包含智能问答、AI 测肤、智能选品、商品百科和朋友圈营销文案，支持文字、语音、图片与文件等交互方式。

移动端需要把持续生成的内容、多轮会话和业务结果组织在一起，同时处理授权、权限、上传和网络异常等情况。

## 我的角色

我负责项目从 0 到 1 的前端开发，搭建 Vue 3 移动端 Web 应用，完成用户体系、路由鉴权、请求拦截与统一异常处理。

我的责任是应用前端及其业务交互，不包括训练底层 AI 模型。

## 关键实践

### 组织流式会话

基于 SSE 封装可中止、可超时的流式请求，完成协议增量解析、Markdown 渲染、异常反馈与会话状态更新，支持历史消息、重新生成和新建会话。

与一次性请求不同，流式对话需要在内容持续到达时维护界面状态，还要让用户明确知道请求是否仍在进行、是否被中止或已超时。

### 连接业务助手与商品信息

落地 AI 测肤、智能选品、魔介百科和朋友圈文案四类业务助手，通过结构化条件、多轮问题引导、输出数据提取与商品接口联动提供业务结果。

业务助手的前端除了呈现文本，还要组织输入条件与后续动作，让回答能够连接具体的业务场景。

### 处理多模态输入与异常

实现语音、图片和文件输入，处理录音权限、语音识别、文本转语音与文件上传，并支持请求中止、超时反馈及重复发送控制。

技术栈包括 Vue 3、Vite、Vant 4、Pinia、Vue Router、Axios、SSE、markdown-it、Web Audio API 与微信 JS-SDK。

## 交付范围

完成移动端应用框架、流式会话、业务助手及多模态输入相关前端功能。本页暂不公开用户会话、内部接口协议与业务截图。

## 后续复盘方向

以下是准备进一步整理的技术问题，不是已发表的结论：

- 增量解析、Markdown 展示与会话状态，如何保持各自职责清晰？
- 中止、超时、重新生成与重复发送，如何组织状态和反馈？
- 录音权限、上传失败与微信环境差异，如何设计可以恢复的交互？
