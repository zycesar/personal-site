# 王永忠个人站设计规格

## 1. 项目目标

为王永忠建设一个长期可维护的中文综合个人站，兼顾求职展示与个人技术品牌。网站突出“前端开发者正在成长为全栈工程师”的定位，通过项目案例、技术文章和成长路径，让访客快速理解个人能力与方向。

首版成功标准：

- 网站可通过腾讯云上海地域的公开临时地址访问。
- 项目与文章使用 Markdown 维护，修改内容后可以重新构建发布。
- 桌面端和移动端均具备完整、清晰的浏览体验。
- 网站具备基础 SEO、RSS、Sitemap、无障碍和深浅色主题能力。
- 域名备案完成后，无需改造应用即可切换至 `https://zycesay.cn`。

## 2. 已知条件与范围

- 项目当前为空，尚无既有技术栈或内容资产。
- 网站语言为中文，代码结构为后续国际化预留空间，但首版不实现语言切换。
- 当前没有可直接上线的真实项目和文章素材。首版提供明确标注为“示例”的内容结构，不虚构工作经历、项目结果或个人身份信息。
- 域名为 `zycesay.cn`，注册状态正常，DNS 由 DNSPod 管理，有效期至 2027-03-10，目前尚未完成 ICP 备案。
- 首版不包含数据库、登录、管理后台、评论、站内搜索和在线表单。

## 3. 技术架构

### 3.1 核心技术

- Vue 3：实现自定义页面组件与交互。
- VitePress：提供 Vite 构建、Markdown 路由、静态生成与内容站基础能力。
- TypeScript：约束组件属性、内容元数据与配置。
- CSS 变量与组件级样式：实现视觉系统、响应式布局和主题切换，不引入重量级 UI 组件库。
- Vitest：覆盖内容解析和关键工具函数。
- Playwright：覆盖主要页面和关键交互。

VitePress 使用完全自定义主题。最终页面应表现为现代产品化作品集，而不是文档站。

### 3.2 静态数据流

1. 作者编辑项目 Markdown、文章 Markdown 或个人资料配置。
2. 构建阶段校验 Frontmatter 必填字段并读取内容。
3. VitePress 生成列表页、详情页、首页聚合信息及 SEO 元数据。
4. 构建输出为静态 HTML、CSS、JavaScript 和资源文件。
5. 静态产物同步至腾讯云 COS。

浏览器运行时不依赖数据库或内容 API。即使客户端 JavaScript 未成功加载，核心文本和链接仍应可阅读、可导航。

## 4. 信息架构

### 4.1 页面

- 首页 `/`：身份定位、精选项目、最新文章、成长路径、联系方式。
- 项目列表 `/projects/`：展示所有项目摘要、技术栈和状态。
- 项目详情 `/projects/<slug>`：按背景、角色、挑战、方案、结果和反思组织案例。
- 文章列表 `/posts/`：按时间倒序展示文章、分类和标签。
- 文章详情 `/posts/<slug>`：正文、目录、发布日期、标签和相邻文章导航。
- 关于我 `/about/`：更完整的个人介绍、技能方向和全栈成长路线。
- 404：提供清晰说明与返回首页入口。

### 4.2 首页浏览顺序

1. 身份与定位：王永忠，前端开发者，正在向全栈工程师成长。
2. 精选项目：首版展示两个项目卡片。
3. 最新文章：首版展示三篇文章卡片。
4. 成长路径：前端基础与业务交付 → 工程化与架构意识 → Node.js、数据库与部署。
5. 联系区域：GitHub、邮箱等公开联系方式；未配置的链接不渲染。

头像区域首版使用“永”字品牌图形，不生成或使用虚构人物头像。

## 5. 内容模型

### 5.1 项目

项目位于 `projects/*.md`，Frontmatter 至少包含：

- `title`：项目名称。
- `description`：列表摘要。
- `date`：发布日期或完成日期。
- `tags`：技术标签。
- `featured`：是否进入首页精选。
- `draft`：是否仅保留在本地构建中。
- `cover`：可选封面路径。

正文按照背景、角色、挑战、方案、结果和反思组织。示例项目必须设置可见的示例标识。

### 5.2 文章

文章位于 `posts/*.md`，Frontmatter 至少包含：

- `title`：文章标题。
- `description`：文章摘要。
- `date`：发布日期。
- `category`：单一主分类。
- `tags`：标签列表。
- `draft`：是否仅保留在本地构建中。
- `cover`：可选封面路径。

文章列表按日期倒序排列，草稿不进入生产构建、RSS 或 Sitemap。

### 5.3 个人资料

个人资料集中在一个 TypeScript 配置模块中，包括姓名、角色描述、简介、成长路径和外部链接。未填写的外部链接不会显示，不使用假邮箱或假社交账号。

## 6. 视觉与交互

视觉方向为“现代产品 / 作品集”：白色或深色中性背景、紫蓝强调色、明确的网格、圆角卡片和较强的标题层级。整体气质应清爽、亲和、专业，避免终端风、黑客风或通用简历模板感。

- 顶部导航在所有主要页面保持一致。
- 项目与文章通过卡片和标签建立信息层级。
- 页面切换使用轻量过渡，卡片提供克制的悬停反馈。
- 自动跟随系统深浅色偏好，并允许访客手动切换。
- 尊重 `prefers-reduced-motion`，在减少动画模式下关闭非必要动效。
- 外部链接有明确标识，并在新标签页安全打开。
- 手机端使用单列布局，导航收纳为可访问菜单。

## 7. SEO、可访问性与性能

- 每个页面拥有独立的标题、描述、Open Graph 元数据和规范链接。
- 生成 `sitemap.xml`、`rss.xml` 和 `robots.txt`。
- 使用语义化 HTML、键盘可操作控件、可见焦点和合理颜色对比度。
- 图片包含替代文本、明确尺寸和适合的懒加载策略。
- 中文字体使用系统字体栈，不依赖可能在中国大陆加载失败的第三方字体服务。
- 生产环境 Lighthouse 的性能、SEO、最佳实践和无障碍四项分数目标均为 90 或以上。

## 8. 异常处理

- 构建阶段校验内容元数据；必填字段缺失或类型错误时终止构建并输出具体文件与字段。
- 图片加载失败时保留布局尺寸，并显示替代文本或中性占位样式。
- 未知路由进入自定义 404 页面。
- 发布前检查站内链接、静态资源引用和关键外部链接格式。
- 部署脚本失败时不覆盖当前可用版本，并返回非零退出状态。

## 9. 测试与验收

### 9.1 自动验证

- TypeScript 类型检查通过。
- Vitest 验证 Frontmatter 校验、排序、草稿过滤和链接辅助函数。
- VitePress 生产构建通过。
- Playwright 验证首页到项目/文章/关于页的导航、主题切换、移动端菜单和 404。
- 静态链接检查无失效的站内链接。

### 9.2 人工验收

- 在 375px、768px 和 1440px 视口检查布局。
- 检查浅色、深色及减少动画三种系统偏好。
- 检查上海 COS 临时地址可从公网打开主要页面。
- 检查刷新详情页不会返回错误。
- 运行 Lighthouse 并确认四项分数目标。

## 10. 部署与域名

### 10.1 备案期间

- 在腾讯云 COS 创建上海地域（`ap-shanghai`）存储桶。
- 开启静态网站托管并配置首页与错误页。
- 将 VitePress 生成的 `.vitepress/dist` 内容同步到存储桶。
- 使用 COS 提供的 `*.cos-website.ap-shanghai.myqcloud.com` 地址作为首版公开访问地址。
- 不在备案完成前将 `zycesay.cn` 绑定至中国大陆托管资源。

### 10.2 备案完成后

- 为 `zycesay.cn` 配置有效的 TLS 证书。
- 在 DNSPod 添加所需解析记录。
- 优先将站点接入 EdgeOne；若账号或产品能力不满足静态站点需求，则回退至腾讯云 CDN。两种路径均启用 HTTPS、压缩与静态缓存。
- 将站点规范 URL、Sitemap 和 RSS 的域名切换为 `https://zycesay.cn`。
- 验证 HTTP 到 HTTPS、裸域名和 `www` 域名的唯一跳转策略，默认以裸域名 `zycesay.cn` 为主站。

## 11. 后续阶段

首版稳定后可以按独立项目逐步增加：英文内容、站内搜索、真实项目案例、评论系统、访问统计，以及基于 Node.js 与数据库的内容管理后台。这些能力不进入首版验收范围。
